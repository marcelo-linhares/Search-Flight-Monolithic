ArchitectureArquitetura

A DDD monolith (Node.js, 8 bounded contexts) plus an Expo React Native client, in one Yarn-workspaces monorepo. Described as of the develop branch, October 2026.Um monólito DDD (Node.js, 8 contextos delimitados) mais um cliente Expo React Native, em um monorepo Yarn workspaces. Descrito conforme a branch develop, outubro de 2026.

Why this matters for the thesis. The TCC asks how DDD and GenAI affect the organization and productivity of engineering teams when refactoring monoliths. This architecture is the artifact under study: boundaries are explicit enough that a context can be extracted later without redesign.Por que importa para o TCC. O TCC investiga como DDD e GenAI afetam a organização e a produtividade de equipes ao refatorar monólitos. Esta arquitetura é o artefato estudado: as fronteiras são explícitas o bastante para extrair um contexto depois sem redesenho.

System overviewVisão geral do sistema

apps/mobile

Expo SDK 57, React Native 0.86, Expo Router, Zustand, client EventBus. Runs on an in-memory mock server unless EXPO_PUBLIC_API_URL is set.Roda sobre um servidor mock em memória, a menos que EXPO_PUBLIC_API_URL esteja definida.

apps/api

Node.js monolith, Express 5, in-process event bus, in-memory repositories.Monólito Node.js, Express 5, barramento de eventos em processo, repositórios em memória.

packages/domain-events

The server↔client contract: DTOs and only the events the UI must show (WatchSuspendedDueToCredits, WatchReactivated, BalanceRestored, CreditsPurchased, PriceDropDetected, AlertReceived). Server-internal events stay in the monolith.O contrato servidor↔cliente: DTOs e apenas os eventos que a UI precisa exibir (WatchSuspendedDueToCredits, WatchReactivated, BalanceRestored, CreditsPurchased, PriceDropDetected, AlertReceived). Eventos internos do servidor ficam no monólito.

packages/ui (design tokens, shared components, logomarktokens de design, componentes compartilhados, logomarca) · packages/config (tsconfig, prettier)

Layers inside each contextCamadas dentro de cada contexto

Presentation Express 5 in src/http, beside the contexts. Routes call use cases and queries only; one error handler maps DomainError subclasses to HTTP codes.Express 5 em src/http, ao lado dos contextos. Application Use cases and event handlers. Orchestrate; no business rules.Casos de uso e handlers de eventos. Orquestram; sem regras de negócio.
Domain Aggregates record events (pullDomainEvents()); value objects are frozen and compared by value; events are frozen facts built by makeEvent. No I/O.Agregados registram eventos (pullDomainEvents()); value objects são congelados e comparados por valor; eventos são fatos congelados criados por makeEvent. Sem I/O.
Infrastructure Repositories (findBy… / save), adapters, bus. Vendor vocabulary is translated here.Repositórios (findBy… / save), adaptadores, barramento. O vocabulário de fornecedores é traduzido aqui.

Composition root and layoutRaiz de composição e estrutura

src/app.js is the only place that knows every context: it creates the bus and calls registerBilling, registerLedger, registerWatch, registerScheduler, registerSearch, injecting the flight provider and a clock.src/app.js é o único lugar que conhece todos os contextos: cria o barramento e chama registerBilling, registerLedger, registerWatch, registerScheduler, registerSearch, injetando o provedor de voos e um relógio.

MVP shortcuts that are clean to undoAtalhos de MVP fáceis de desfazer

  • In-process event bus → message queue/Kafka (handlers only depend on publish(event)).Barramento em processo → fila de mensagens/Kafka (handlers dependem apenas de publish(event)).
  • In-memory repositories rebuild a fresh aggregate on every read, so tests catch a forgotten save(); swap for database repositories with the same methods.Repositórios em memória reconstroem um agregado novo a cada leitura, então testes pegam um save() esquecido; troque por repositórios de banco com os mesmos métodos.
  • Fake flight provider → real providers behind FlightPort.Provedor de voos fake → provedores reais atrás de FlightPort.
  • Temporary auth: x-user-id header until an Identity context exists.Autenticação temporária: header x-user-id até existir um contexto Identity.

TestingTestes

Jest with three projects: unit (domain, test-first/TDD), integration (use cases and handlers with in-memory repos and bus; includes the P0 credit-exhaustion flow with a fake clock; HTTP contract via supertest) and stage (end-to-end, placeholders only). Coverage thresholds: 80% branches, 85% functions and lines.Jest com três projetos: unit (domínio, test-first/TDD), integration (casos de uso e handlers com repositórios e barramento em memória; inclui o fluxo P0 de esgotamento de créditos com relógio falso; contrato HTTP via supertest) e stage (ponta a ponta, apenas placeholders). Limites de cobertura: 80% branches, 85% funções e linhas.

FrontendFrontend

app/ Expo Router routes are composition points only: they fill screen slots with module components.Rotas do Expo Router são apenas pontos de composição: preenchem slots de tela com componentes dos módulos.
src/modules/ One folder per context (watch, billing, ledger, notification, search, pricing), each with its own Zustand store.ts, events.ts, components and screens. A module never imports another module's store.Uma pasta por contexto (watch, billing, ledger, notification, search, pricing), cada uma com seu store.ts Zustand, events.ts, componentes e telas. Um módulo nunca importa o store de outro.
shared/bus Client EventBus mirroring the server's emitter. Cross-module data flows through it: WatchSuspendedDueToCredits updates both the watch store and the notification store.EventBus do cliente espelhando o emissor do servidor. Dados entre módulos fluem por ele: WatchSuspendedDueToCredits atualiza o store de watch e o de notification.
shared/api http.ts for the real backend, mock/ for the in-memory server. USE_MOCK is true when EXPO_PUBLIC_API_URL is empty.http.ts para o backend real, mock/ para o servidor em memória. USE_MOCK é verdadeiro quando EXPO_PUBLIC_API_URL está vazia.
shared/push Mock mode pushes straight into the bus; real mode uses expo-notifications, loaded lazily and skipped in Expo Go.O modo mock empurra direto no barramento; o modo real usa expo-notifications, carregado sob demanda e ignorado no Expo Go.

UI rules: suspended watches always show the top-up call to action; the Ledger store is the only balance source; alert preferences live on their own screen. Scheduler and Integration have no mobile module. The mobile app has no automated tests yet (checks: yarn typecheck, expo-doctor).Regras de UI: watches suspensos sempre exibem o CTA de recarga; o store do Ledger é a única fonte de saldo; preferências de alerta ficam em tela própria. Scheduler e Integration não têm módulo mobile. O app mobile ainda não tem testes automatizados (verificações: yarn typecheck, expo-doctor).
