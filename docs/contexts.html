Communication rulesRegras de comunicação

  • Contexts talk only through domain events; never import another context's aggregates, repositories or stores.Contextos conversam apenas por eventos de domínio; nunca importam agregados, repositórios ou stores de outro contexto.
  • No shared value objects: each context redefines what it needs (Billing's PaymentAmountVO mirrors Search's MoneyVO).Sem value objects compartilhados: cada contexto redefine o que precisa (o PaymentAmountVO do Billing espelha o MoneyVO do Search).
  • Events are past-tense, immutable facts (CreditsPurchased, not AddCredits).Eventos são fatos imutáveis no passado (CreditsPurchased, não AddCredits).
  • The Ledger is the only source of the credit balance.O Ledger é a única fonte do saldo de créditos.
  • Handlers are idempotent where possible and use a publish(event) interface, so the in-process bus can later become a queue.Handlers são idempotentes sempre que possível e usam a interface publish(event), permitindo trocar o barramento em processo por uma fila.

Event Storming outcomeResultado do Event Storming

The first context set had five contexts. An Event Storming session (three AI agents: a business domain expert, a DDD architect and a platform engineer) flagged missing contexts, which led to Watch Management, Billing and Ledger. Source: docs/EXPERIMENT_LOG.md, entry 3.O primeiro conjunto tinha cinco contextos. Uma sessão de Event Storming (três agentes de IA: especialista de domínio, arquiteto DDD e engenheiro de plataforma) apontou contextos ausentes, o que levou a Watch Management, Billing e Ledger.
